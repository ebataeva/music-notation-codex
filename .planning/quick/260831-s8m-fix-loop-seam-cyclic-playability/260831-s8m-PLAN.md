<objective>
The engine promises "no leaps larger than an octave between consecutive notes" and keeps that promise — but only for the *linear* note sequence. `previous_pitch` starts as `None` in bar 1 and the last note is never compared against the first. The product ships a **loop**: `app/pages/loop_coach.py:262` renders `<audio ... loop>`, and the cellist repeats the figure live. The last-note -> first-note pair is a real, physically executed adjacency that no line of code and no test ever looks at.

Existing guards `tests/test_loop_engine.py:390` and `:440` walk `zip(notes, notes[1:])` — n-1 adjacencies out of n. The n-1 -> 0 pair is checked nowhere.

Measured on current code (900 generations, `Am F C G` x 3 biases x 300 seeds): the seam exceeds an octave in 17% of runs, max 22 semitones. Minimal counterexample — one chord, one bar:

    Am, dark_trip_hop, seed=1, bias=default  ->  A2 C3 E3 A2 C3 E3 A3 C4
    max leap inside the bar 7 semitones; on repeat C4 -> A2 = 15 semitones

Everything is formally correct: pitches in range, bar sums to 4.0, chord tones clean, MusicXML valid, `187 passed`.

Reference standard (measured on the hand-authored presets via `build_score`): seams of 0, 7, 0, 0 semitones — three of four return to the exact opening pitch. The human author freely takes 14-semitone leaps *inside* a bar but never at the seam. The code's priorities are exactly inverted.

Pedagogical tail: `voice_leading_steps` is always `None`, and `how_to_end` explains how to finish the loop while knowing nothing about its hardest physical moment.

Output: generated loops close on or near their opening pitch; the seam becomes a first-class, tested invariant; the trace and the explainer name it.
</objective>
